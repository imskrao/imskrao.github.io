What I do

Three things I get hired for

The work that actually moves a product: deciding how the frontend is put together, making it fast, and making the team around it faster.

Frontend architecture

Module boundaries, state strategy, design-system foundations and the build pipeline - the decisions that are expensive to reverse. I make them explicitly, write them down, and keep them reviewable.

Performance & accessibility

Core Web Vitals treated as a budget, not a report card. Profiling real sessions, cutting bundle weight, fixing the render path - and shipping interfaces that work with a keyboard and a screen reader.

Leading the build

Breaking large features into shippable slices, reviewing code so it teaches something, and mentoring engineers into owning their own areas. Most of the leverage is here, not in my own commits.
